### Stale Failure Counter Pattern (Two Instances)

**Jobs**:
- `elephas:ingest` (f7ac50c7e09f): `consecutive_failures=2`, `last_status=ok`, `last_error=None`, last run 15:54 — successful
- `weave-enrichment-health-check` (7fd9801171ad): `consecutive_failures=1`, `last_status=ok`, `last_error=None`, last run 15:25 — successful

**Pattern**: `consecutive_failures > 0` BUT `last_status=ok` AND `last_error=None`. The failure counter was incremented during a previous failure spell but was not reset when the job succeeded. This is a **stale counter** — distinct from both "stale error" (old traceback path) and "active failure" (consec > 0 AND last_status=error).

**Rule**: If `last_status=ok` AND `last_error` is null → job is healthy, regardless of counter value. Do not escalate.

## Lessons

1. **Fix persistence across sessions**: When a fix is applied to a Python file while the gateway is running, the old code stays in memory. Always check file mtime against gateway start time to determine if a restart is needed.

2. **Stale counter vs stale error — two distinct patterns**:
   - Stale error: `last_error` traceback references old script path → compare against current `script` field
   - Stale counter: `consecutive_failures > 0` but `last_status=ok` and `last_error=None` → counter not reset on success
   - Both mean: job is healthy, no action needed

3. **Weekly jobs and 48h check**: Weekly cron exprs like `0 6 * * 0` won't have run in 48h unless the scan happens on the right day. Check the cron expr before flagging as overdue.
