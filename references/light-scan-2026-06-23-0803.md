## Key Lesson

When config.yaml is modified to remove a broken provider, the gateway must restart to pick up the change. Jobs that ran before the restart will show stale `status=error` with the old provider error, but `consecutive_failures=0` (scheduler doesn't count pre-fix failures). These are **stale error states**, not active errors. Verify by checking: (1) config no longer contains the broken provider, (2) gateway has restarted since the config change, (3) no new errors in gateway log after restart. Do NOT apply pause/resume to "fix" these — they'll self-verify on next run.
